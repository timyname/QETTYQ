# Публичный AI: реализация, бюджет и оставшийся блокер

Обновлено: 2026-10-20. Этот отчёт заменяет первоначальный план до подключения D1.

## Фактический статус

По результатам проверки и публикации root:

- Публичная версия **v6 развёрнута**.
- Реализация public AI, интеграция API и D1 готовы. D1 provisioned; таблица и схема проверены.
- В Sites runtime отсутствует `OPENAI_API_KEY`. Статус помощника — `API_KEY_MISSING`; вместо генерации возвращается явно обозначенный deterministic fallback.
- Платных публичных AI-вызовов не было. Локальная успешная проверка провайдера — отдельная проверка, а не доказательство работающего публичного AI.

В рамках этого обновления изменён только данный документ. Новых исследований, проверок UI, обращений к API, чтения секретов и деплоя не выполнялось.

## Реализованный режим

GPT‑5.5 формирует объяснение на основании evidence, собранного серверным retrieval из афиши. Живое HTTP-получение источника и генерация по найденным записям — source-evidence RAG; fallback-снимок сохраняет свой реальный статус и свежесть.

**Hosted web search OpenAI в публичном режиме выключен.** Не обещаем произвольный поиск по интернету: его расходы не входят в принятый расчёт.

Запрос ограничен одним plain Responses вызовом: default service tier, `store:false`, без hosted tools, attachments, скрытой истории/продолжения conversation, background и автоматических повторов. Инструкции, JSON evidence и схема ответа вместе ограничены 8000 UTF‑8 байт; выход — 1200 токенов. Точная GPS пользователя не передаётся.

Публичный ответ использует строгий JSON-контракт `intent`, `evidenceIds`, `message`. Код проверяет IDs реально переданных записей, допустимость текста и источников. Сгенерированные цены, бесплатность, язык, наличие мест, удобства, расписание и гарантии маршрута не подменяют факты карточек. Цитаты берутся только из выбранных серверных evidence; отклонённый ответ не получает цитат. Это консервативная защита, не универсальная гарантия семантической истинности любого текста.

## Общий бюджет

Разрешённый новый public-бюджет: **$10**. Фиксированный approval ID — `qettyq-public-ai-10usd-20261020-v1`; перезапуск, новая сессия или деплой его не обнуляют. Старую локальную тестовую резервацию не сбрасывали.

На каждый разрешённый запрос заранее безвозвратно резервируется **$0.50**. Максимум — **20 резерваций** на весь approval, а не на каждого пользователя. Суммы хранятся целыми micro-USD: общий предел `10000000`, одна резервация `500000`.

Консервативный расчёт для принятого plain-request режима:

```text
50000 входных токенов × $5 / 1000000
+ 1200 выходных токенов × $30 / 1000000
= $0.286; резерв = $0.50 без возврата остатка.
```

50000 — запас для входа и framing при ограниченном UTF‑8 payload, а не утверждение «8000 байт равны 8000 токенов». Проверяются возвращённые usage, модель, default tier и отсутствие tool calls. Тарифы GPT‑5.5 проверялись по [официальной странице модели](https://developers.openai.com/api/docs/models/gpt-5.5). Hosted tools исключены намеренно; [тариф поиска](https://developers.openai.com/api/docs/pricing) включает дополнительные расходы.

Это **application reservation cap**, не обещание абсолютного лимита итогового счёта OpenAI с любыми account-specific charges. Неизвестная стоимость не считается нулём. [Официальный spending controller](https://developers.openai.com/cookbook/articles/per_run_spending_controller_responses_api) также различает учёт приложения и ограничения поставщика.

## D1 и fail-closed поведение

`public-ai-budget.ts` выполняет атомарный conditional INSERT в `qettyq_ai_public_reservations`. В одной операции проверяются общий остаток, request ID, cooldown сессии и дневной предел. Лимиты: одна попытка сессии в минуту, до десяти в UTC-сутки; гостевую сессию можно сменить, поэтому это не обещание устойчивого per-person ограничения.

Одновременно допускается один pending-запрос на общий approval. Подтверждённое допустимое usage завершает запись; неопределённый результат или нарушение accounting переводит её в blocked. При остановке Worker до завершения pending сохраняется и препятствует новым вызовам. Нет автоматического expiry, возврата средств, сброса approval или файлового/process-memory fallback.

Отсутствие D1, схемы, ключа, разрешающих флагов, средств либо подтверждения accounting закрывает платный путь. После неизвестного исхода требуется проверка оператором; пересоздавать ledger ради продолжения запрещено.

## Оставшийся безопасный setup-блокер

Владелец явно разрешил использовать существующий ключ из локального env. Решение reuse-vs-new уже принято; повторно спрашивать его не нужно. Однако локальный env и production runtime Sites — разные хранилища.

Доступный native Sites setter принимает plaintext `value` с `is_secret:true`, но не принимает локальный путь, stdin, ciphertext или secret reference. Документированного безопасного bridge из локальной Node-памяти непосредственно в этот native setter не найдено. `is_secret:true` защищает возврат значения после сохранения, но не решает передачу локального секрета в аргумент инструмента.

Вывод ключа через stdout, `nodeRepl.write`, обычный tool output, чат или исходный код не является допустимым переносом. Недокументированные RPC/endpoints и обход ограничений не применялись. Ключ не читался и не раскрывался ради устранения этого блокера.

## Следующий проверяемый шаг

Владелец вводит существующий ключ непосредственно в защищённое поле runtime Secrets Sites (`OPENAI_API_KEY`), либо становится доступен документированный secure-input/secret-reference bridge. Затем root применяет новую env revision штатным деплоем сохранённой версии и проверяет статус без вывода значения секрета.

Только после устранения `API_KEY_MISSING` допустима ограниченная проверка реального публичного ответа через существующий D1 reserve-контур, в пределах того же общего бюджета. Сейчас сайт опубликован, но публичная генерация AI ещё не активна. Эта подзадача завершена отчётом; автоматическое продолжение не запущено.
