## Основание и направление

Прочитаны frontend-design, design-intelligence, ui-systems и локальные Next.js guides по CSS Modules и Client Components. Сохраняем одобренный городской UI QETTYQ: жемчужное стекло, нефритовый текст, лайм только для выбранного состояния. У бюджета один заметный жест: быстрый выбор суммы вместо формы из одного поля.

Из09 восстановлены крупный блок суммы, маленькие быстрые суммы, отдельное понятное отсутствие ограничения. ## Реализация

Новый контролируемый компонент:

```tsx
<BudgetControl
  value={context.budget}
  onChange={budget => updateContext({ budget })}
  strict={context.strictBudget}
  onStrictChange={strictBudget => updateContext({ strictBudget })}
/>
```

Главный агент может заменить им прежние budget label/input и strict checkbox внутри panel. Компонент содержит собственную подпись, fieldset и compact input, повторять внешнюю подпись не нужно.

- Четыре быстрые суммы:0,3000,5000,10000 KZT на человека.
- Пятый широкий вариант: «Без ограничений», значениеnull.
- Ручной number input всегда видим. Доступное имя строго сохранено: `Бюджет на человека, ₸`. Родительский E2E с fill продолжает находить поле.
- null никогда не преобразуется в0. Очистка поля выбираетnull.
- Допустимы только конечные целые значения0…1 000 000. Недопустимое изменение не вызывает onChange и показывает конкретную ошибку. NaN/Infinity не отправляются.
- Выбор0 включает strict. Выход из0 снимает автоматически включённый strict. Между ненулевыми суммами явный strict пользователя сохраняется. Безлимитный вариант снимает ограничение по известной цене, его можно включить обратно checkbox.
- Checkbox не скрывает неопределённость. При0 и выключенном пользователем strict подпись меняется и не обещает подтверждённо бесплатную выдачу.
- Пять пресетов имеют aria-pressed. Группа названа, input связан с описанием, ошибка rolealert, все пресеты не ниже44px. Видимый focus, reduced motion без scale.
- CSS Modules с локальными токенами и достаточно специфичными selectors не дают текущему `.app input:not(...)` стереть стили суммы. Новых зависимостей и шрифтов нет.

## Короткие UX-заметки по16 и24

1. **Карта фоном экрана.** В16 карта занимает почти весь доступный viewport. Поиск и фильтры плавают поверх с отступом16px, зона действия44–48px. Вместо вложенной «карточки карты» внутри длинной страницы стоит отдать карте flex1, убрать лишние вертикальные intro-блоки. Реальный map-provider остаётся интерактивным, растровый генеративный фон географию не заменяет.
2. **Bottom sheet.** Свернутый примерно24–30% высоты экрана, раскрытый60–70%. Внутри короткая выбранная карточка с квадратной миниатюрой, временем/стоимостью и одним главным действием. Sheet и внутренний scroll не перекрывают четыре нижних раздела. Атрибуция карты всегда видима. Декоративную ручку делать интерактивной только если реально переключает состояние.
3. **Маркеры.** Нефрит для остальных точек, лайм для выбранной. Одинаковые40–44px hit areas не означают огромные glyphs. Кластеры показывают число, одиночные точки могут показывать категорию. Нельзя терять связи marker/card при смене фильтра и zoom. Геометрию/события без координат не придумывать.
4. **План24.** Карта сверху, список A/остановки/B в sheet, компактная сводка времени и бюджета рядом с заголовком. Фактический сетевой маршрут можно выделить тёмным нефритовым штрихом и более широким светло-лаймовым halo. При нынешнем straight-line fallback маршрут по улицам не рисуется. Время/цена с unknown остаются unknown. Кнопки других транспортов допустимы только при настоящем расчёте, иначе явно недоступны.
5. **Навигация.** В generated16 нарисованы старые условные табы. Не переносить их: действующая схема остаётся Для тебя / Поиск / Карта / Профиль, настройки сверху. Для24 действие «Сохранить план» не должно сообщать о брони или о подтверждённом посещении.
