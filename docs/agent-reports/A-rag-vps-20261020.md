## Files and contracts

### `src/server/datastore/sqlite.ts` / `schema.ts`

`openDatastore({path?, production?, migrate?}) -> DatabaseSync`.

- Node 24 `node:sqlite`, foreign keys, WAL, synchronous FULL, 5-second busy
  timeout, no extensions, database/WAL/SHM permissions `0600`.
- Local default: ignored `.sites-runtime/qettyq.sqlite`.
- Production requires an explicit absolute `QETTYQ_DATABASE_PATH`, e.g.
  `/var/lib/qettyq/qettyq.sqlite`, on the **QETTYQ-only persistent volume**.
  Relative paths and `:memory:` are rejected in production.
- Migration is explicit (`migrate:true`) and transactional; do it at controlled
  startup/deployment, not inside request handling. Do not bundle this module
  into the Cloudflare Worker, browser, or Edge runtime.
- SQLite durability requires the actual persistent local volume and backups;
  container rebuilds alone are not persistence. Do not run this file on an
  unverified network filesystem or share it with another project.

Tables: `data_sources`, `venues`, `venue_opening_hours`, `events`,
`event_occurrences`, `fact_provenance`, `media_rights`, `ingestion_runs`,
`source_records`, `source_refresh_leases`, `memory_clients`, `memory_consents`,
`memory_profiles`, `memory_messages`, `memory_visits`, the existing-name
`qettyq_ai_public_reservations`, and `ai_ledger_migrations`.

Events have source-scoped provider identities; occurrences are separate rows.
Only observed identical Sxodim provider IDs share a parent event. Titles are not
fuzzy-merged; recurrence is not guessed. Occurrence-level language, UTC start/end,
`Asia/Almaty`, price kind/minor units/basis, availability, provenance and expiry
remain separate. Unknown is not free, open, available, or a fabricated coordinate.

### `src/server/datastore/events-store.ts`

`createEventsStore(db)` exports:

- `registerSource(DatastoreSourcePolicy)`: explicit independent permission for
  persist/display/LLM/fetch, credit and minimum refresh interval. Fetch defaults
  to **false**. Candidate documents are not operational source permission.
- `importSxodim(snapshot)`: transactionally validates and upserts the existing
  approved adapter's normalized snapshot. Repeated content hash is a no-op;
  an older snapshot cannot replace newer data. Invalid input rolls back without
  destroying last-good data. Missing records in a bounded partial refresh are
  **not inferred cancelled**. Their own expiry eventually excludes them.
- `importPlaces(Place[], {sourceId, expiresAt})`: explicit approved POI snapshot
  import with per-field provenance; no opening-hours invention or map-image
  downloading. Caller supplies a reviewed expiry policy, not a fabricated
  indefinite freshness guarantee.
- `retrieve({text, context, now?, allowStale?, near?, forLlm?})`: normalized
  SQLite candidate retrieval, followed by the existing deterministic
  `retrieveEventEvidence`. Dates use Astana's `Asia/Almaty` calendar. Existing
  genre/negative-query/date/budget/group-price safeguards are retained. Defaults
  exclude expired and future-fetched records. Explicit stale retrieval returns
  snapshot/stale evidence and warnings, never falsely live data. LLM retrieval
  additionally requires `allowLlm` on the source.
- `near:{lat,lon,radiusKm}` uses **straight-line** distance only. Missing event
  coordinates are excluded from a required radius, not geocoded by guessing.
  This is not walking/driving time or a verified road route.
- `retrievePlaces({context,query?,now?,visitStartMs?,near?,requireOpen?,limit?})`:
  literal name/category/address/tag search, preferences, goal, budget, radius,
  estimated visit-duration bound and observed opening-hours checks. Returns
  `feasibility:'uncertain'`, `travelMinutes:null`, distance quality, provenance,
  required credit and explicit unknowns. It does not claim transit feasibility.
- `saveOpeningHours(OpeningHoursFact[])`,
  `openingStatus(venueId,fromMs,untilMs) -> 'open'|'closed'|'unknown'`:
  the **fact's own sourceId must be approved**; OSM permission for a venue does
  not grant permission to import a museum website. No Saturday fact => unknown.
  The whole interval must fit observed, unexpired hours for `open`; conflicting
  facts, partial overlap, cross-day intervals and incomplete schedules remain
  unknown. `requireOpen:true` excludes unknown status rather than promising open.
- `snapshotCache.read()/write()`: compatible with the existing
  `createLiveEventsService({cache})`. This cache alone performs **zero** fetches.
- `acquireSourceRefresh(sourceId,now?)`: single conditional SQL UPSERT shared
  between connections/processes. Reserve **before** fetching; an hourly policy
  permits one attempt per hour even if the previous attempt failed. Persisted
  cooldown survives process restart. Root must wrap the existing bounded loader
  with this method; simply passing the cache does not enforce the global lease.

Suggested root wiring, not run here:

```ts
const db = openDatastore({ path: process.env.QETTYQ_DATABASE_PATH, migrate: true });
const store = createEventsStore(db);
// Register reviewed source policies and explicitly import the approved baseline.

  cache: store.snapshotCache,

      throw new Error('SOURCE_REFRESH_COOLDOWN');
    }
    return fetchLiveAstanaEvents(); // existing fixed-host, bounded source adapter

// Root API can retrieve stored evidence after the service refreshes/writes cache.
```

Use last-good snapshot on a denied refresh or provider failure, with its real
expiry/data mode. No mass fetch, pagination crawl, external geocoding, or new
donor is introduced by this repository. Static POIs must not be advertised as
timed events or currently open venues.

### `src/server/datastore/client-memory.ts`

`createClientMemory(db, clock?)` exports `grantConsent`, `hasConsent`,
`saveProfile/readProfile`, `appendMessage/messages`, `markVisited/visits`,
`aiContext`, `revokeConsent`, `deleteClient`, `purgeExpired`.

- Root authenticates the opaque session token before calling the repository.
  Only a SHA-256 namespaced hash is stored. This is not a cross-device login.
- No implicit guest persistence or migration of browser preferences/messages.
  Separate explicit consent scopes: `profile`, `dialogue`, `ai_transfer`,
  `visits`. Explicit retention choice: 24 hours or 30 days.
- Profile schema permits only interests/locale/goal/time/budget, **no GPS**.
  Dialogue redacts decimal coordinate-like strings best-effort; this is not a
  general personal-data detector or encryption.
- At most 24 stored messages, max **4,000 UTF-8 bytes each**, role/mode validated,
  idempotent message IDs; conflicting IDs rejected. Row expiry is captured at
  write time: renewing consent does **not** extend old messages indefinitely.
- `aiContext` requires `ai_transfer`, and independently respects profile/dialogue/
  visits consents; history is at most the most recent six permitted messages.
  The existing provider may further clip its own bounded prompt.
- Visits are recorded **only** through `markVisited` after explicit visits
  consent, for an existing entity and a non-future time. Label remains
  `user_confirmed`, not independently verified. At most 100 retained visits.
  A save, source click, ticket link or route launch is not a visit.
- Revoking scope deletes its data; deleting the client cascades. Expired rows
  are not returned; root must schedule `purgeExpired()` for physical cleanup.
- Existing browser memory currently retains up to 24 messages without this new
  server TTL; do not claim it has already been migrated or server-encrypted.
  Cookie authentication, opt-in/revoke UI, deletion API, backup retention and
  production encryption/access policy remain root integration/deployment work.

### `src/server/pilot/chat-history.ts`

## Follow-up: working opt-in memory API (2026-10-20 UTC)

Implemented `server/memory/{contracts,http,service}.ts` and these API routes:

- `GET /api/memory`: authenticated state/restore, **never creates identity**.
- `POST /api/memory/consents {scope,retention}`: explicit opt-in; scopes
  `profile|dialogue|ai_transfer|visits`, retention `session_24h|persistent_30d`.
- `DELETE /api/memory/consents {scope}`: delete that scope's data; last active
  consent also deletes identity and clears the cookie.
- `PATCH /api/memory/profile {likedTags,locale,goal?,minutes?,budget?}`.
- `POST /api/memory/messages {id,role,text,mode}`: optional user history import;
  its contents remain **untrusted personal context**, not catalogue evidence.
- `POST /api/memory/visits {entityKind,entityId,visitedAtMs}`: explicit confirmed
  action only; no future dates or invented entities, no inferred attendance.
- `DELETE /api/memory`: cascade logical active-data deletion and clear cookie.

All require a valid current guest session; mutations also enforce origin/fetch
site checks. Persistent memory identity is separately authenticated by an opaque
server-random256-bit `__Host-qettyq_memory` cookie (HttpOnly, Secure in production,
SameSite=Strict, host-only Path=/, bounded Max-Age) and SQLite hash lookup.
No body/header clientId is accepted; unknown/ambiguous cookies cannot restore
another identity and are not adopted during opt-in. A fresh guest session after
process restart can restore the same consented profile/dialogue using the cookie.
This is per-browser possession, not an account login or cross-device sync.

Frontend state: `{available,enabled,storageMode:'sqlite_opt_in',consents,profile,
messages,visits,expiresAt,historyTrust:'untrusted_personal_context'}`.
Messages have `{id,role,text,mode,createdAtMs}`, at most24. Missing scope yields
null profile/empty history/empty visits. Initial scope grants must be sequential
so the first response's cookie accompanies the next grant. Errors are safe
503 unavailable/409 missing identity/403 missing scope, with no RAM persistence.

Hosted runtime now exposes the ready memory service:
`readForAI(request)` returns null without existing identity, guest authentication
and independent ai_transfer consent; otherwise permitted preferences, ≤6 bounded
history messages and user-confirmed visits. `recordExchange(request, exchange)`
requires dialogue consent/existing identity and atomically saves the pair; it
never creates identity. Its `{stored,reason}` is safe to report. Root owns chat
wiring; UI must not duplicate these server-recorded messages.

Row TTL is enforced by reads and physical SQLite row cleanup at startup, on
requests and an unref'ed60-second process timer. Runtime close disposes the timer.
Only additive expiry indexes were added; no table reset or budget modification.
Revocation/deletion does not claim forensic erasure from old WAL/backups; root's
volume encryption, checkpoint and backup-retention policy remain operational work.

Structured GPS/address/clientId fields are prohibited. Tags are canonical ASCII
interest identifiers. Recognizable address markers, GPS-like decimals and URLs
are conservatively omitted from stored dialogue. This is best-effort free-text
privacy suppression, **not** proof that every imaginable natural-language address
can be detected. SQLite is not encrypted by this service; do not promise otherwise.

Independent source policy bridge `events.canSendToLlm(sourceId)` checks persisted
allow_persist+allow_display+allow_llm; unknown/error is false. A person's memory
consent never grants a publisher new LLM rights. The bridge covers OSM/Sxodim and
any separately reviewed registered source, not hardcoded new-provider approval.
