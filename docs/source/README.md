# QETTYQ · пакет задания для Codex

**Это комплект документации для сборки сервиса, не готовое приложение.**
Основной документ `PRD.md` самодостаточен и содержит все продуктовые решения,
сценарии, технические требования и инструкции команде AI-агентов.

## Что находится в пакете

| Файл | Назначение |
|---|---|
| [PRD.md](PRD.md) | Полное задание: продукт, источники, RAG, маршруты, дизайн, 30 сценариев, роли и приёмка |
| [AGENTS.md](AGENTS.md) | Короткие правила и указатель для агента, работающего в этой папке |
| [START_PROMPT.md](START_PROMPT.md) | Один стартовый промпт для оркестратора в Codex |
| [README.md](README.md) | Эта инструкция |

## Как начать

1. Распакуй пакет в отдельную папку `QETTYQ` и открой её в Codex/редакторе с Codex.
2. Скопируй промпт из `START_PROMPT.md` и отправь в рабочую сессию.
3. Агент проверит окружение, создаст проект и начнёт сборку по PRD.

Если существует репозиторий QETTYQ, добавь документы в его рабочую ветку,
сохранив имеющиеся инструкции и пользовательские изменения. Не заменяй без
проверки существующий `AGENTS.md`. Не запускай задание в корне другого продукта.

Для запуска достаточно одного `PRD.md`: в нём есть стартовая команда и все
инструкции. Остальные файлы упрощают передачу и навигацию.

## Что должно получиться

QETTYQ: веб-сервис выбора досуга в Астане. Пользователь задаёт цель, время,
бюджет и маршрут, отмечает интересные идеи свайпами и получает 1–3 подходящих
варианта с объяснениями, расчётами и источниками.

Оркестратор координирует девять специализированных ролей. Они занимаются данными,
базой, backend, AI, дизайном, frontend, сценариями, QA и презентацией.
Реальная параллельная работа зависит от возможностей среды. Если субагенты
недоступны, PRD предусматривает последовательное исполнение без имитации запуска.

## Что не нужно делать заранее

Не нужно заполнять этот файл ключами, покупать сервер, придумывать API афиши или
вручную составлять сотни мест. Источники и способы сбора должен исследовать агент.
Базовые решения уже приняты: Астана, RU, KZT, гостевой режим, mobile-first,
проверяемые данные и строгие ограничения по времени/бюджету.

## Что всё же может потребовать твоего действия

Для реальных LLM/картографических API может понадобиться безопасное подключение
ключа и подтверждение лимита расходов. Для публикации сайта, репозитория,
YouTube-ролика и конкурсной заявки нужны доступ и разрешение.

Ключи не вставляются в PRD или чат. Используется доверенный setup среды. Без LLM
приложение может работать в честно обозначенном режиме поиска, но генеративный
RAG в таком состоянии не считается выполненным.

## Как контролировать результат

Проверяй `docs/STATUS.md`, когда агент его создаст. В нём должны быть фактические
источники, режим данных, статусы AI и маршрутов, запущенные тесты, ограничения
и конкурсные файлы. Открой продукт и пройди базовый сценарий самостоятельно.

Команд приложения в этом пакете пока нет. Они описаны как требования к исполнителю
в PRD. Агент обязан создать `package.json`/реальные скрипты и заменить этот README
документацией проверенного запуска после реализации. Не запускай `pnpm dev` в
пустой папке до создания приложения.

## Источники и актуальность

Дата подготовки: 19 октября 2026 года. В PRD есть реестр официальной технической
документации и кандидатов на источники городских данных. Проверка условий,
доступов и актуальных правил конкурса входит в работу исполнителя.
Точное время закрытия конкурсной формы в пакете не утверждается.

## Передача другому агенту

При необходимости передай `PRD.md`, созданные исходники и актуальные
`docs/STATUS.md`/`docs/NEXT_STEPS.md`. Историю переписки пересылать не требуется.
