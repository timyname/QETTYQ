# QETTYQ · Поиск и помощник — контракт интерфейса

Статус: дизайн к реализации в Penpot, не доказательство работающего AI. Город: Астана. Основание: пользовательские комментарии, PRD §§6–10,11,13 и существующие данные `data/places.json`. Разработка приложения и публикация в этот этап не входят.

Направление: спокойная живая переписка в жемчужно-нефритовой палитре QETTYQ, с лёгким объёмом стекла и проверяемыми карточками вместо рекламных обещаний.

## 7. Служебные состояния и доступные действия

Не каждый блок обязан быть нажимаемым. Каждый элемент, оформленный как control, обязан иметь честный исход. Недоступный endpoint нельзя заменять одинаковым переходом на29.

| Контрол/состояние | Поведение |
|---|---|
| Внешняя ссылка источника | Открывает точный allowlisted sourceUrl в новой вкладке; без координат пользователя/текста чата в URL |
| Новый диалог | После сообщений overlay `Начать новый диалог?` / «Этот разговор останется на устройстве, если включена память.» Кнопки «Отмена» и «Начать». Если хранение не реализовано, текст заменить на «Текущий разговор будет очищен.» |
| Контекстная плашка/карандаш | →08–10; по возврату сохранить transcript и обновить только явно подтверждённые условия |
| Send пустой | Disabled, не реагирует; aria-disabled. Не отдельный «ошибочный экран» |

## 8. Motion и layout QA

- Новое сообщение: opacity0→1 и translateY8→0 за180ms; никакой печати фактов по символам с прыгающей высотой карточки.
- Обработка: один неброский loader, не мигание всего экрана. Статусы заменяются без изменения высоты панели.
- Card hover только desktop: подъём2px за140ms; touch press scale0.98 за120ms. Focus outline2px jade с offset3px.
- Reduced motion: fade100ms или мгновенно; loader заменён статичным статусом.
- Белое стекло ограничено composer/dock/пузырями, фон не размыт до потери контраста. Оговорки тёмные читаемые, не почти прозрачные.
- При увеличении текста: растёт message/card, работает scroll внутри transcript; composer/dock не перекрываются. Не уменьшать font-size ради fit.
- Не более одного primary действия на карточке. Рядом с источником и всеми исходами отдельные hitarea; без невидимых наложенных rectangles, перехватывающих другую кнопку.
- Реальный runtime: авто-scroll только если пользователь около низа. Если читает выше — компактный «Новый ответ ↓» вместо прыжка.
