## Метод

Для каждого кандидата учитывалась собственная interaction **либо interaction предка** до корневого screen board. Отсутствие interaction у text label внутри работающей кнопки не считалось дефектом. У фонового прямоугольника и поверхностного текста, созданных соседними слоями, общего интерактивного предка может не быть: такие зоны отдельно помечены как риск hit testing, а не автоматически сломанная кнопка.

Обычные описания, прогресс, декоративные иконки, атрибуции изображения и информационные badges не обязаны нажиматься. Главная цель — не превратить весь текст в ссылки, а чтобы каждый **нарисованный actionable control** имел проверяемое действие или понятное объяснение ограничения.

Уровни: P0 — нарушает понимание/основной сценарий; P1 — неработающий видимый контрол/существенная логическая ошибка; P2 — улучшение полноты и предсказуемости. «Предложено» ниже не означает «уже реализовано».

## Уточнение критического дефекта геометрии

Нативные API вернули у 03, например:

```text
row / Астана      x38 y261 w350 h17
row / Алматы      x38 y261 w350 h17
value / Астана    x38 y283 w350 h15
value / Алматы    x38 y283 w350 h15
```

На 08 аналогично совпали все четыре labels и values. В `final-polish.js` причина — `labels.indexOf(s)`: `findShapes` вызывается заново для поиска индекса, а wrappers объекта не обязаны быть тем же JS-reference. Получается `i=-1`, поэтому `333−72=261` и `355−72=283`. Стабильный индекс по `shape.id` либо `.forEach((shape,index)=>…)` на одном массиве устраняет эту категорию ошибки. Нужна повторная проверка **всех** затронутых экранов, а не только08.

19 не имеет этого конкретного наложения после отдельного `labels.forEach((s,i)=>…)` в `final-details.js`: ряд label y333/395/457…, value y355/417/479…. Контролы фильтров там всё равно остаются некликабельными в данном снимке.

Проверка bounding-box текста дополнительно находила пересечение `chrome / wordmark` и `chrome / brand-dot`. Это одна намеренная составная марка, а не две конфликтующие инструкции; в список дефектов пересечения этот результат не включён. Само геометрическое пересечение text bounds не всегда означает пересечение глифов.

## Что уже связано и не надо ошибочно считать дефектом

- Основные `action / …` из 01–45 преимущественно имеют native interactions. Labels внутри них покрыты интерактивным ancestor; отдельно привязывать каждый label не требуется.
- Четыре `tab / Для тебя`, `/ Поиск`, `/ Карта`, `/ Профиль` имеют 14/27/16/32 на проверенных основных макетах. В 19 dock сознательно неактивен, пока открыт modal.
- `chrome / city`, `/ settings`, большинство `/ back` связаны. Навигационная связь ещё не гарантирует правильное восстановление состояния инициатора; это отдельный сценарный тест.
- 14/15 фон `feed / candidate-card` связан с21; 29 фон `chat / candidate-card` связан с21. Вопрос остаётся в покрытии sibling content и идентичности выбранного объекта.
- 33 «Открыть OpenStreetMap» имеет настоящий external URL `https://www.openstreetmap.org/node/455447680`. Не нужно заменять его вымышленными provider endpoints.
- `chip / 15 идей досуга`, `chip / Около 2 минут` на04 и badges «Иллюстрация категории» — информативные метки, не элементы выбора. Их не требуется делать произвольными кнопками.
- `profile / guest-card`, обычные сведения33/34/40 и объяснения ошибок43 — не обязательно действия. При желании добавить drill-down его текст должен объяснять, что именно откроется, а не превращать каждый абзац в неочевидный target.

## Фактически выполненные проверки

Выполнены read-only Node ESM команды через `connect()`/`execute()` официального локального MCP: инвентаризация native layers 01–45 (с исключением пересобираемой05–07), ancestor interaction traversal, чтение сокращённых action targets/opacity/disabled-reason, попарные пересечения text bounding boxes. Также выполнены `rg` и чтение локальных файлов сборки. Успешные диагностические команды завершились exit code0.

Два первых запроса были избыточно подробными: выдача tool была обрезана; вывод interaction destination затем явно сокращён до имени/типа цели. Эти обрезанные выдачи не используются как доказательство полноты. Финальные компактные запросы дали конкретные данные для замечаний выше.

**Не проверено этим аудитом:** реальные browser clicks, runtime ввод, настоящие drag/sliders, сохранение памяти/черновиков, clipboard/system share, Google Maps, геолокация, AI, модерация, маршрутизация. Наличие target не равно успешной операции приложения. После исправлений нужен отдельный recheck; этот файл сам по себе не объявляет замечания закрытыми.
