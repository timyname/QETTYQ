# QETTYQ: структура конкурсной презентации v4

Хронометраж: 5–7 минут вместе с короткой демонстрацией.
Кейс: НИЦ Smart City, «ИИ-помощник по прогулкам в городе Астана».
Статус: локальный рабочий прототип на 19 октября 2026 года.

## 1. QETTYQ подбирает досуг в текущем контексте

На слайде:

- Астана, локальный прототип
- 15 выборов интересов
- до трёх вариантов с источниками

Речь:

«QETTYQ помогает выбрать, куда пойти в Астане с учётом времени, бюджета, точки старта и текущих интересов. Две минуты являются целью интерфейса, которую ещё нужно измерить на пользователях».

## 2. Мы сфокусировались на двух проверяемых сценариях

На слайде:

1. Человек задаёт ограничения и получает 1–3 места.
2. Человек открывает карту событий и проверяет источник.

Речь:

«В задании предложено несколько типов запросов. Мы собрали одну рабочую вертикаль для персональной выдачи и отдельный map-first explorer событий. Эти сценарии пока не объединены в один поток».

## 3. Контекст задаётся до поиска

На слайде:

- 120 минут
- 5000 ₸ на человека
- старт у Байтерека
- 15 коротких выборов

Речь:

«Время и бюджет становятся явными условиями расчёта. Неизвестная цена не считается бесплатной. Карточки работают кнопками. Drag gesture пока отсутствует».

## 4. Данные собраны в датированный snapshot

На слайде:

- 80 реальных POI из OpenStreetMap
- ограниченный импорт через Overpass
- координаты, категории и provenance
- четыре вручную отобранных события

Речь:

«Повторяемый import script и data validation есть в репозитории. Основная выдача использует OSM snapshot. События являются отдельным статическим набором со ссылками на издателей. Live feed не подключён».

## 5. Код сначала проверяет допустимость

На слайде:

`snapshot → hard filters → ranking → explanation`

- время и расстояние проверяет код
- unknown остаётся unknown
- до трёх результатов получают краткое объяснение

Речь:

«Retrieval берёт кандидатов из локального snapshot. Код фильтрует и ранжирует их. Объяснение использует только поля выбранного кандидата. Детерминированный режим работает без ключа. Адаптер OpenAI готов, но live RAG-вызов в текущей среде не подтверждён».

## 6. Результат объясняет ограничения

На слайде:

- источник каждой записи
- расстояние от старта
- приблизительное время
- явная пометка неизвестной цены

Речь:

«В текущем примере три места близки к заданному контексту. У них нет подтверждённой цены, поэтому интерфейс просит уточнить её у первоисточника. План показывает оценку по прямому расстоянию, а не точный пешеходный маршрут».

## 7. Карта работает без закрытых API

На слайде:

- Leaflet и OpenStreetMap
- четыре маркера событий
- внешний Google Maps URL
- Google Places и Routes не подключены

Речь:

«Карта уже даёт городской контекст и сохраняет атрибуцию OpenStreetMap. Внешняя ссылка Google Maps не требует API key, но QETTYQ не получает из неё ETA или геометрию. Для встроенных Google API нужны billing и ограниченные credentials владельца».

## 8. Проверки покрывают рабочую вертикаль

На слайде:

- 13 unit и integration тестов
- 4 mobile E2E сценария
- 30 Given/When/Then сценариев в документации
- build, typecheck и data validation

Речь:

«Тринадцать автоматических тестов и четыре мобильных E2E прошли в зафиксированном локальном прогоне. Матрица из тридцати сценариев шире текущего покрытия и не выдаётся за тридцать автотестов».

## 9. Приватность и неопределённость являются частью ответа

На слайде:

- точные координаты не нужны модели
- гостевая сессия живёт 24 часа
- backend поддерживает undo и удаление данных
- UI удаления пока не подключён

Речь:

«Локация используется для расчёта и не должна попадать в URL или prompt. Серверная часть поддерживает гостевую сессию, идемпотентные реакции, undo и удаление данных. В текущем интерфейсе реакции хранятся локально, а пользовательская кнопка удаления ещё отсутствует».

## 10. Следующий результат объединит рекомендации и карту

На слайде:

- одни кандидаты в списке и на карте
- live RAG smoke с разрешённым ключом
- точный walking route через согласованного провайдера
- событийный feed с подтверждёнными правами

Речь:

«Сейчас это честный локальный прототип. Публичный deployment, доступность GitHub URL, YouTube demo и конкурсная отправка не подтверждены. Следующий проверяемый шаг состоит в объединении персональной выдачи с картой, после чего можно подключать разрешённые провайдеры. Целевой адрес репозитория: github.com/timyname/QETTYQ».

## Короткая демонстрация

1. На стартовом экране назвать Астану единственным городом пилота.
2. Задать 120 минут, 5000 ₸ и старт у Байтерека.
3. Пройти карточки кнопками и открыть результаты.
4. Показать источник, unknown-цену и приблизительный план.
5. Открыть карту событий и внешний Google Maps URL.
6. Закончить фразой: «Встроенные Google API и live RAG здесь не имитируются».
