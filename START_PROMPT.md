# Стартовый промпт для Codex

Скопируй текст блока в Codex, открытый в папке с `PRD.md`. Не запускай его в папке
другого продукта, которую нельзя менять. Если у тебя только один файл PRD, этого
достаточно: вспомогательные документы агент должен создать самостоятельно.

```text
Создай QETTYQ по приложенному PRD.md. Прочитай файл полностью, при необходимости
частями по оглавлению. Это основное техническое и продуктовое задание; контекст
другого чата для него не нужен.

Ты главный оркестратор и архитектор. Выполняй работу инструментами, а не только
описывай план. Начни с проверки окружения, доступных навыков/инструментов,
существующих файлов, инструкций и Git-статуса. Сохрани пользовательские изменения.
Создай короткий AGENTS.md, если его нет, и рабочий docs/STATUS.md.

Привлеки настоящих субагентов по ролям из раздела 14 PRD: источники и сбор данных,
база данных, backend и маршруты, AI/RAG, дизайн и design skills, frontend,
пользовательские сценарии, QA/безопасность и презентация. Запускай только реально
поддерживаемые средой субагенты и не более четырёх независимых задач одновременно.
Если субагенты недоступны, исполни те же роли последовательно, не имитируя их запуск.
Дай каждому конкретную область файлов, входы и проверяемый результат.
Общие контракты и конфигурацию контролируй сам.

Собери сервис целиком: онбординг → время/бюджет/точки A и B → свайпы интересов
и предложений → реальные POI/события → поиск и расчёты → RAG-объяснения →
1–3 рекомендации → детали/план/источники. Пользователь должен пройти это через
интерфейс, без ручной подмены данных в консоли. Не ограничивайся лендингом.

Сам найди и проверь открытые источники по Астане. Реализуй воспроизводимый сбор,
реестр прав и provenance. Не выдумывай данные, интеграции, расписания и цены.
Соблюдай ограничения источников и отличай реальные фотографии от иллюстраций.

Дизайн сделай оригинальным и mobile-first. Используй механику свайпов, но не
копируй чужой бренд. Дизайнер должен проверить доступные навыки и подходящие
GitHub-референсы, лицензии и содержимое до использования. Красивый макет не
заменяет рабочие состояния, адаптивность, доступность и визуальную проверку.

При наличии разрешённой конфигурации подключи GPT API на сервере через безопасный
setup среды. Не требуй ключ в чате и не сохраняй его в публичные файлы. Без ключа
продолжай в явно обозначенном deterministic-режиме; не называй RAG завершённым.
Не создавай платную инфраструктуру, не делай публичный push/deploy и не отправляй
конкурсные материалы без соответствующего разрешения.

Работай по контрольным воротам G0–G3. Сначала реальный сквозной сценарий и P0,
затем независимые проверки, оставшиеся функции и конкурсные материалы.
Подготовь README с проверенными командами, сценарии, ограничения, тестовый отчёт,
презентацию и материалы видеодемо. При наличии инструментов создай и проверь
PPTX/PDF и локальное видео. Не выдумывай YouTube URL или статус принятой заявки.

Не останавливайся после планирования. Вопросы задавай только при реальном блокере:
секрет, обязательный недоступный ресурс, платное действие или публикация.
Остальные решения принимай по defaults PRD и фиксируй в DECISIONS.md.
В конце покажи фактически созданные файлы, проверенные команды запуска,
выполненные тесты, рабочие URL при наличии и конкретные незакрытые ограничения.
```
